# Core/Storage — notes

SwiftData models, blob encryption, retention. Sync is off in v1 (`AGENTS.md`), but the model shape is kept CloudKit-mirror-compatible, which the CloudKit lines below describe. See `AGENTS.md` for the encryption-at-rest security invariant and module boundaries.

## High-Risk Zones

| Path | Blast radius |
|---|---|
| `Models/ClipboardItem.swift` | The central model; preview text is encrypted (see invariant below) and a wrong accessor leaks empty/plaintext data app-wide. |
| `Models/ClipboardBlob.swift` | `encryptedData` is the at-rest blob; round-trip tests assert on-disk bytes differ from plaintext. |
| `Sources/Core/Crypto/BlobEncryption.swift` | AES-GCM-256 with a per-install Keychain key (not Secure Enclave wrapped, ADR 0002); the process-lifetime key cache (below) governs Keychain prompts. |
| `RetentionPolicy.swift` / `Models/RetentionPruner.swift` | Deletes history; an off-by-one prunes user data irreversibly. |

## Key Invariants

- IMPORTANT: **Blob and preview ciphertext is bound to its item** (ADR 0002). Seal with `BlobEncryption.associatedData(itemID:field:)` and set `aadBound` / `previewAADBound`; open through `ClipboardBlob.decryptedData()` or pass `blob.associatedData` / `item.previewAssociatedData`. A new place that writes `encryptedData` or `previewCiphertext` must do the same, or the clip cannot be read. Choose the item id before sealing (`ingest` takes `preferredItemID`, else `UUID()`), never after the model exists.
- **`@Attribute(.externalStorage)` is the only sane way to sync blobs via CloudKit.** Don't write a custom blob handler — the framework gives `CKAsset` semantics for free.
- **CloudKit-mirrored stores require every property to be optional OR have a default.** SwiftData inherits this from `NSPersistentCloudKitContainer`. Add defaults; don't leave a non-optional bare property.
- **`@Attribute(.unique)` is a local hint only** — CloudKit cannot enforce uniqueness server-side. Use `contentHash` for dedupe; don't trust uniqueness.
- **CryptoKit `AES.GCM.SealedBox.ciphertext` and `.tag` are slices with non-zero `startIndex`.** On macOS 26, subscripting at `[0]` traps (SIGTRAP) because `startIndex == nonceLength` (12). Always normalize with `Data(sealed.ciphertext)` before subscript operations.
- IMPORTANT: **A clip's title, note, tags, page title and site name are sealed into `metadataCiphertext` (ADR 0002).** Use `customTitle`, `userNote`, `tags`, `ogTitle` and `ogSiteName`; the `legacy*` columns are only for the launch migration. They cannot appear in a `#Predicate`.
- IMPORTANT: **A clip's search vector is sealed into `embeddingCiphertext` (ADR 0002).** Use `embeddingData`; `legacyEmbeddingData` is only for the launch migration (`sealEmbeddings`). It cannot appear in a `#Predicate`. A cold read of 5,000 sealed vectors takes about 20 ms, and `PreviewTextCache` keeps them opened until the history locks. Ingest computes the vector on a background task through `StorageService.embedder` (`TextEmbedding`), from at most `SemanticIndexer.maxEmbeddedCharacters` characters (the model's memory grows with the text: 685 MB at 50,000 characters, an abort at 1,000,000): outside a normal launch it is `NoEmbedding`, a test names one in its `StorageEnvironment`, and `waitForBackgroundWork()` returns once the vectors are stored.
- IMPORTANT: **`ClipboardItem.previewText` is `""` for every item that is not a parsed colour or masked (ADR 0002, `ColorPreviewPolicy`).** The plaintext preview is stored encrypted in `previewCiphertext` + `previewNonce` and reached via the `displayPreviewText` accessor. Always use `displayPreviewText` (or `gridPreview`, which already routes through it) for search, semantic embedding, Spotlight, AppleScript exposers, paste fallback, etc. Reading `previewText` directly on a text/code item returns the empty string. Only colours (and the masked preview of a sensitive item, via `sensitivityMaskedPreview`) stay readable; `displayPreviewText` returns `previewText` unchanged when there is no ciphertext, which is also how previews from before the migration still read.
- **Heavy data never lives in a `ClipboardItem` row.** Every `@Query` loads every column, and `propertiesToFetch` does not avoid it (measured: 82 MB vs 82 MB for 5,000 items). Source-app icons resolve by bundle ID (`SourceIconCache`; `sourceIconData` is legacy and always nil), link preview images live in the encrypted `LinkPreviewImageStore` (deleted with their item and on clear), and `HistoryMemoryTests` holds a 5,000-item fetch under 40 MB. Embeddings (`embeddingData`, about 3 KB each) are the remaining inline column. A view that needs a count over the history asks the actor (`privacySnapshot`, `commandBarSuggestions`: tags are sealed, so they are opened page by page there), not a second whole-table `@Query`.
- IMPORTANT: **A Keychain error is not a missing key.** Only `errSecItemNotFound` means the key is absent (`KeyPresence`); a locked or interaction-not-allowed Keychain is "unavailable" and gets Try Again / Quit, never the dialog whose second button wipes the history. When `SecItemAdd` reports a duplicate, adopt the stored item instead of using a key or id that was never stored.
- **One copy has a size limit, and a refusal is shown** (ADR 0006, `ClipSizePolicy`): ingest and append throw `ClipSizePolicy.TooLarge`, and the capture handler shows its message as a two-minute shelf banner. A new capture path goes through `StorageService.ingest`, so it inherits the limit; never write a blob around it.
- **`BlobEncryption` caches the AES-256 key in a process-lifetime singleton.** Once `loadOrCreateKey()` returns, subsequent calls (from any `BlobEncryption()` instance, on any thread) read the cached key without round-tripping through `SecItemCopyMatching`. This prevents per-call Keychain ACL re-prompts on dev builds where the CDHash drifts between launches.
- **A `@Query` for a model type not registered in the injected container silently returns empty — no crash, no error log.** If a SwiftData model isn't appearing in a view, check which container is injected at that level of the hierarchy (`appState.historyContainer` vs `localContainer`) before debugging the query itself. All models queried in `OverlayRootView` / `CommandBarView` must be in `historyContainer`.
- **A preference is a `Setting` key, never a string literal** (ADR 0012, `SettingsRegistryTests`): `@AppStorage(Setting.x)` in a view, `AppDefaults.store.value(for: Setting.x)` anywhere else, so the default is spelled once and a background reader sees what the Settings pane shows. Add the key to `Setting.allNames` too.
- IMPORTANT: **Save through `saveOrRollback()` (a `ModelContext` extension, on the actor and on the main context), never `context.save()`** (`StorageSaveTests` scans all of `Sources/`). SwiftData keeps a failed save's pending changes in the actor's context, so the next unrelated save would commit a half-made clip. A whole-history pass uses `forEachClip` (a page of 50, saved and yielded between pages, ADR 0007), never a fetch of every row.
- **An import takes the one path in `HistoryExporter` (`insertNew`/`makeItem`)**: the type is read again from the text, a secret is masked, a preview that cannot be sealed skips the record, and a file over `maxImportBytes` or `maxRecords` is refused. Never trust the `type` a file carries.
- **A preview that cannot be sealed fails the copy** (`sealPreview`, `previewSealer` seam for tests); it is never stored as plain text.
- IMPORTANT: **A picture, or a text over 100 KB, is saved before it is judged (ADR 0006).** `ingest` stores it with `analysisPending = true`, no preview and no sensitivity; `StorageService.startAnalysis` then reads it (OCR), asks the model, scans for secrets and calls `finishAnalysis`, which stores the masked preview or the OCR text and clears the mark. Anything that describes a clip (the last-item file, a backup, the search text) must wait for that: `finishAnalysis` writes the last-item file, `itemRecord` skips a pending clip. A new place that reads previews of every clip must expect an empty one. A test that ingests a picture and then reads its verdict calls `waitForBackgroundWork()`. Nothing may suspend between the second duplicate check and the insert in `ingest` (the sequence number is taken before it).
- **The history index (`HistoryIndex`, ADR 0007) holds folded plaintext** of every preview, title, note and tag, so it is dropped wherever `PreviewTextCache` is cleared for the lock (`HistoryStore.dropSearchText`). A field the shelf filters by is a field of `HistoryRow` and a case in `HistoryIndexParityTests`.
- **`StorageService` depends on a `StorageEnvironment`, not on globals** (W-07): the last-item store, text recognizer, picture screener, link-preview store, embedder, preview sealer, GIF fetcher, clock, rules, sequence counter and device ID arrive at `init(modelContainer:environment:)`. The app builds `.live(...)` once; a test builds `.testing { $0.x = … }` (no last-item file, no language model, whatever the host) instead of patching a service after it exists. Only `updateRules` and `updateClock` stay, because rules change with Settings and a test moves the clock mid-way. A new dependency is a field of the environment.
- **A clip is edited through `ClipEditor`**: change, `saveOrRollback`, tell the person on failure, refresh the search row, tell the shelf its filter may have moved. A view that edits a clip with its own `try? context.save()` skips three of those.
- **Versioned launch migrations are declared in `LaunchMigration.standard(service:)` and run by `LaunchMigrator`, one after another.** A migration that kept rows (`.incomplete`) leaves its version alone so the next launch tries again; a new one is a new entry in that list, with its own `Setting` version key.
- IMPORTANT: **Undo is in memory, sealed, and wiped with the history (ADR 0008).** `UndoHistory` (via `StorageEnvironment.undoHistory`) holds `ClipSnapshot`s of stored, still-sealed bytes, never plaintext. Only `deleteItems(reason: .user)`, `deleteCollection`, `ClipEditor.edit` and the pin and shortcut functions record. A new path that wipes history must call `undoHistory.clear()`; a new column on `ClipboardItem` or `Pinboard` must be copied by `ClipSnapshot` / `PinboardSnapshot` (`ClipDeleteUndoTests` fails until it is). `UndoPolicy` decides what is never held.
- **A clip's text signature, paste days and remembered fill-in values live in `ItemMetadata`** (sealed, ADR 0017), not in columns: no migration, and the backup does not carry them (it lists metadata fields by name), so after a restore `AppState.startSimilarityWork` signs the clips again. `StorageService.similarity` is the in-memory `SimilarityIndex`: every path that deletes clips must remove their ids (`deleteItems` and `clearNonPinned` do), `AppState.stopSimilarityWork` drops it at the lock, and a clip brought back by Undo is indexed again only at the next launch or unlock. Signatures are never computed for a secret, a clip that expires or text outside 40 to 2,000 characters (`TextSignature.isEligible`); the idle backfill (`signMissingClips`) pauses while the history is locked or Low Power Mode is on.
- **`CoreDirectoryCycleTests` fails on a new reference from one Core directory's types to another's** (and on an edge that is gone but still listed). New shared value types go in `Core/Model`, which depends on nothing.
## Lessons

- **The store is versioned** (`PestoSchemaV1`, `PestoMigrationPlan`). A schema change that keeps the same classes, such as `#Index`, reaches new stores only: SwiftData sees no change, and an old store opens without it. It needs a real copy of the old models, a V2 stage, and a test against an old on-disk store, never an in-memory one.
- **A memory test of storage uses a file-backed store** (`ModelContainerSetup.openSynced(cloudKitEnabled:storeURL:)`), never `makeInMemory`, which keeps a blob several times (570 MB for a 98 MB picture against 313 MB on disk). Measure picture work in pixels with a standalone probe first, one process per case, then pin it (`LargePictureMemoryTests`). A byte limit does not bound a decode: a flat 400-megapixel PNG is 7 MB and peaked at 3.9 GB.
- **The embedding model allocates in proportion to its input** (2,000 characters peak at 61 MB, 50,000 at 685 MB, 1,000,000 aborts with `std::bad_alloc`), so `SemanticIndexer.embeddingInput(for:)` caps the text at 2,000 characters.
- **Time a performance worry before it shapes a design.** Sealing the search vectors was deferred as "slow" and then measured: about 20 ms to open 5,000 vectors cold.
- **Find a footprint problem with the right tool**: `footprint <pid>` reports the peak as well as the current value, `vmmap` shows freed-but-resident regions ("Malloc Large (empty)"), and `MallocStackLogging=1` with `malloc_history <pid> -allEvents` names who allocates. `heap` showing far less than the footprint means the allocator is holding freed blocks.
