# Features/Overlay — notes

The bottom-shelf overlay panel, floating window, glass shelf background, and the paste-trigger timing that runs inside the hide animation. May import `Core/` but not vice versa. The overlay-open → first-paint budget is < 100 ms (`AGENTS.md`). Every `NSHostingView` here must be `SafeHostingView` (root pitfall, hook-enforced).

## Accessibility naming

- **Every AX layer must be named, and the repeated names are structural.** `AccessibilityAuditTests` fails on any unnamed node, including ones SwiftUI creates for the `LazyHStack`. Do not remove either half of a name pair (window and hosting view, ScrollView and LazyHStack) without re-running the audit; `test_overlay_namesEachRegionOnce` locks the count.
- **A shared open or closed state that both a SwiftUI view and an AppKit key coordinator set belongs on `AppState`**, not in the view's `@State` (the inline collection creator, `isCreatingCollection`).

## High-Risk Zones

| Path | Blast radius |
|---|---|
| `OverlayWindowController.swift` | Show/hide animation + paste trigger; the layer-transform and completion-block invariants below prevent a SIGSEGV that silently swallows the paste. |
| `PinnedWindowController.swift` | Pinned panel style bits decide whether auto-paste hits the target or Pesto itself. |
| `ShelfBackground.swift` | Visual identity; reads the focused card's color (invariant below). |
| `OverlayRootView.swift` | Root SwiftUI view over `@Query` results — the place O(n)-in-`body` regressions blow the open budget. |

## Key Invariants

- **Mesh-gradient glow color uses the focused card's `sourceDominantColorHex`, not the hovered card.** Hover is transient; focus is the user's actual attention.
- **Never bind the shelf's scroll position two-way (`.scrollPosition(id: $state)`).** It writes state back while the user scrolls, and a `@State` write re-runs `GridView.body`, which rebuilds every visible card. Programmatic scrolling goes through `ScrollViewReader` and a request value (`scrollRequest`), and `isScrolling` lives in its own `@Observable` (`ShelfScrollState`) that only the cards read. Card identity is the clip's UUID, not its index, or deletes cannot animate.
- **Fire paste in `OverlayWindowController.hide(completion:)`, not with a fixed delay.** The `completion` parameter must be `() -> Void` (NOT `@MainActor @Sendable () -> Void`) because the closure captures non-`Sendable` types like `ClipboardItem`; both caller and callee are already `@MainActor`.
- **No O(n) aggregate over `@Query` results in `var body`, and no view holds a live query over every clip: `GridView` reads `HistoryStore`, which fetches once for both windows and follows saves only while one is on screen** (`UnboundedQueryTests`). The command bar's tag and app chips come from `StorageService.commandBarSuggestions()` through `AppState.commandBarSuggestions`, held in `CommandBarSuggestionsModel` (local `@Observable`, not `AppState`, so the grid is not invalidated): it reloads only while the shelf or the floating window is on screen, 0.5 s after a save, and shows nothing while the history is locked. Any new aggregate follows that shape; at 5,000 items an O(n) pass on the main actor blows the <100 ms overlay-open budget.
- **Close the shelf with `AppState.close(_:)` and a `ShelfExit` (`.dismissed`, `.paste`, `.afterHide`, `.startStack`), never by assigning `isOverlayVisible = false`.** The `didSet` runs the hide handler on every `false`, so a second close in a row used to run it twice and could clear an exit that was about to be used; `close` ignores a dismissal of a closed shelf, and the handler takes the exit once (`takePendingExit`). A periodically refreshed value is assigned only when it changed (`recheckAccessibility`).
- IMPORTANT: **Never set `layer.transform` to a non-identity value inside `CATransaction.setDisableActions(true)` on any visible panel.** AppKit creates a `_NSWindowTransformAnimation` to synchronize the window server whenever the layer transform diverges from the window frame. On macOS 26, this internal animation crashes with SIGSEGV in its `-dealloc` (use-after-free via `_Block_release`) when its autorelease pool is drained during the same CA transaction flush that fires a hide-animation completion block — the completion block (and any paste trigger inside it) silently never runs. Safe pattern: set only `layer.opacity` in the model-state commit; use explicit `toValue` in the slide animation + `fillMode = .forwards, isRemovedOnCompletion = false`; call `layer.removeAnimation(forKey:)` explicitly in the completion block before `orderOut(nil)`.
- **Any `.nonactivatingPanel` with an `onSelect`-style action must (a) install a global `mouseDown` monitor to dismiss on click-outside, and (b) call `hide()` at the top of `show()` to retire any orphaned instance from a prior call.** Non-activating panels cannot receive SwiftUI `.onKeyPress` events — global `NSEvent` monitors are the only keyboard-dismissal option. Omitting either guard causes the panel to float persistently and fire stale actions into the captured app.
- **Floating-window auto-paste requires `.nonactivatingPanel` + `becomesKeyOnlyIfNeeded`.** Without those style bits the act of clicking the pinned panel activates Pesto (the panel becomes key + the running app), `FocusRestoration.capture()` then captures Pesto itself, and the paste either no-ops or pastes into the wrong target. Pinned-window taps route through `AppDelegate.executePasteItem(_:)` (capture focus → write → CGEvent), NOT through `AppState.close(.paste(...))` — the floating window stays visible across pastes.
- **The lock screen asks for Touch ID inside the shelf, not with a system dialog.** `LAContext.evaluatePolicy` alone draws a system dialog that covers the shelf, so `BiometricLockOverlay` puts an `LAAuthenticationView` on screen and evaluates on the same context; each attempt is a fresh view and context (`EmbeddedBiometricPrompt`), started after the lock transition and retried when the system cancels it (`HistoryLockPolicy.shouldRetryBiometric`). The password fallback is the system dialog. Touch ID cannot be automated: check it by hand (`docs/testing.md`) after touching this file.
- **Show on a hidden clip asks for Touch ID inside the shelf too** (`AppState.authenticateInShelf`, shown by `BiometricLockOverlay`), because the system dialog took focus and closed the shelf before the text appeared. Hand check after touching it: open the shelf, Show a masked clip, and the shelf must stay open; a second Show within the window must not ask again.
- **From the non-activating shelf another app stays active, so `NSApp.activate()` is refused.** `AppDelegate.bringToFront` falls back to `NSWorkspace.openApplication(at:configuration:)` with `activates = true`; `SettingsFlowTests` reproduces it with Finder frontmost.
- **Only the global shortcut may open the small menu at the cursor** (`ShelfOpenSource.allowsQuickMenu`, tested). The status menu's Open Shelf, links, AppleScript and intents pass their own source and always get the full shelf: with a caret in the frontmost app they used to get five cards that only a mouse could use. A new route into the shelf names its source.
- **One display rule for every Pesto window** (`TargetScreen.current()`, `TargetScreenChoice`): the display of the frontmost app's frontmost window, then the pointer's. The shelf, the toast, the stack HUD, the floating window's first frame and the AI answer all use it; `NSScreen.main` is the display with the key window, which is rarely the app being pasted into.
- **⌘Z and ⇧⌘Z belong to the grid, and to an empty search field** (ADR 0008). `KeyNavCoordinator` handles them (the shelf is a non-activating panel that never sees the Edit menu's key equivalents); a field editor or a search field with text keeps them for its own text. The Undo offer (`AppState.undoOffer`) is a 30 pt capsule in the band under the cards (the selection bar's slot, `SelectionActionBar.bottomInset`), never a strip over the cards' headers; it holds while the pointer is on it and goes when the shelf closes, so a pointer that never reports leaving cannot pin it. `EditMenuUndo` serves the Settings window and yields to a text field being edited. The delete question says whether the delete can be undone (`UndoPolicy.canHold`).
- **Quick Look state is checked against the real panel before it is trusted.** The panel can leave without the will-close notification reaching `QuickLookPreviewController` (its own Esc, another responder taking it); `reconcileWithPanel()` runs before the arrow-key handler relies on `isOpen`, or every arrow reopened a preview. Esc closes the preview before it closes the shelf. A pending shelf authentication (`AppState.shelfAuthentication`) keeps the shelf open on resign-key and app-activate, like Quick Look does, so the Use Password… dialog can answer.
- **A dragged collection chip shows an insertion bar, not the drop ring.** `ChipDropDelegate` reads the pointer's half (`CollectionReorder.Side`); the ring is for a clip dragged onto a collection. `draggingPinboardID` is cleared on drop and by the drag-end monitor, or the next clip drop would be read as a reorder.
## Lessons

- **The welcome strip, the Appearance preview and the quick menu draw the real `ClipboardCard`** (`SampleCardStrip`), so a card change shows in all of them at once; never build a look-alike card. The website redraws the shelf by hand from `docs/design/website-shelf-spec.md`: a change to a card or the shelf updates that file in the same pull request (`CardSpecDriftTests` pins its numbers to `CardLayout`).
- **The panel height is fixed (`ShelfHeight.chrome` = `commandBlock` + `liftRoom` + `bottomSlot`), and what sits under the cards must fit the band there.** `GridView` owns the one bottom slot (`ShelfHeight.bottomSlot`); a second `.padding(.bottom, 16)` in a root view once overflowed the panel by 6 pt, and the clipped part only showed once the selection bar needed it. The bar floats in the band as an overlay on `GridView` (`SelectionActionBar.bottomInset`) and takes no layout space. `ShelfGeometryTests` measures where the cards and the bar sit in the real panel; a change under the cards needs a `SelectionBarTests` shot at the compact size and with the shelf at the top.

- **A change that lists the shelf animates only when the eye can follow it** (`ShelfMotion.shouldAnimateChange`); search, filters and sorts rewrite the list and stay instant. Everything goes through `Motion`, so Reduce Motion removes it.
- **Hover is earned and a reveal is one-shot.** The keyboard reveal is one clip's id, cleared on expiry, scroll start and any hover; a card closed by Esc, a drag, a menu or the keyboard timeout stays spent until the pointer leaves it. Hover only counts after the pointer moved more than 4 pt since the shelf opened or since the last scroll (`onContinuousHover`). `HoverCardPanel` is never key, so it reports hover through an `NSTrackingArea`, not SwiftUI `onHover`.
- **`scrollTo(anchor: .leading)` ignores row padding**; use `.contentMargins` on the scroll view. The card-size control is an `NSSlider` wrapper (`TickSlider`) because `adjust(toNormalizedSliderPosition:)` does nothing to a SwiftUI `Slider` and SwiftUI draws no tick marks before macOS 26.
- **A `ScrollView` always takes its cap, and `frame(maxHeight:)` does not hug a flexible child.** The hover card measures its text once and gives the scroll view `min(height, cap)`.
- **Never switch a `@ViewBuilder` branch around a modifier that has hooks inside it.** `gatedDrag` once returned `onDrag(...)` or `self` depending on a state; showing a secret flipped it, SwiftUI rebuilt the card and the card's own `onDisappear` hid the text the moment it appeared. Keep the modifier and vary what it does (`onDrag { allowed ? data() : NSItemProvider() }`).
- **A view that relies on being redrawn needs its own state and trigger.** Removing a once-a-second republish broke the recent-searches popover, which only reappeared because of it (`CommandBarView.showsRecentSearches`). When removing a periodic publish, run the UI suites for the surfaces that observe it.
- **A SwiftUI `.contextMenu` cannot be opened from code.** The keyboard route posts a right-click at the focused card's centre (`FocusedCardAnchor`), which keeps one menu definition. The ⌘K key in `KeyNavCoordinatorTests` was the "unbound key" example, so a new shortcut can break that test.
- **A card is one accessibility element** (`.accessibilityElement(children: .ignore)`): a button inside it cannot be found by a UI test and VoiceOver reaches only the named actions. UI tests drive the context menu and read the revealed text from the card's accessibility value; a test that clicks Show on a blurred card does it by normalised coordinate. A popover's text is its accessibility `value`, not its label.
- **A context-menu UI test must not assert on text macOS adds** (Writing Tools adds "Summarize"); assert on titles only Pesto's own section has ("Extract", "AI Actions").
- **Never convert a whole `NSImage` to get pixels** (`tiffRepresentation` encodes every size an app icon holds, 64 MB twice for one app); draw it at the size needed (`SourceAppResolver`, `SourceIconMemoryTests`).
