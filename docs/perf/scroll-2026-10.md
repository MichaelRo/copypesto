# Shelf scrolling, measured (2026-10-01)

The trackpad scroll still felt heavy after the scroll-binding fix. This records what was measured and what
changed, so the next change has numbers to beat.

## How
`scripts/profile-scroll.sh <label> <Pesto.app> [seed]` launches a signed Release build in UI-test mode, shows the shelf,
records an Animation Hitches trace with `xctrace` while a trackpad-like scroll (posted as real scroll-wheel events with
phases and momentum, six sweeps) runs over the shelf, and prints the hitches Pesto caused. The screen must be unlocked.
The "large" seed is 5,000 text clips; "marketing" is 22 clips with pictures, links, a color and code, which is closer to
a real history. Display: 120 Hz, so one missed frame is an 8 ms hitch.

## Result (Release, one run each)
| Seed | Build | Hitches | Hitch time | Worst |
|---|---|---|---|---|
| large (5,000 text) | before | 43 | 358 ms | 8 ms |
| large (5,000 text) | after | 18 | 150 ms | 8 ms |
| marketing (pictures, links) | before | 337 | 2,833 ms | 17 ms |
| marketing (pictures, links) | after | 5 | 42 ms | 8 ms |

Text cards were already close to smooth; the cost was in cards with pictures and links, which is why a text-only scroll
test never showed it.

## What changed
- A card is one flat translucent fill, not its own backdrop blur over the shelf's glass (`adaptiveCardFill`).
- The shadow is cast by that fill alone, not by the whole card, so text and pictures are not blurred again each frame.
- Pictures are decoded off the main thread into a bitmap before the card draws (`PreparedImage`); before, the first draw of
  each picture card decoded it in the middle of the scroll.
- Color detection (three pattern matches per card per redraw) is remembered per text.
- The pointer-moved flag, the animated-image setting and the menu-open signal live in `ShelfScrollState`, so a scroll start
  no longer re-runs every card, and no card holds notification subscriptions of its own.

## Not measured
GPU time per frame, and a real history with GIFs. If the shelf still feels heavy on a real Mac, record a run with that Mac's
own clips (copy the store into a `pesto-` work directory) and look at the Hitches table's "Potential Issue" text.

## Second round: pictures that scroll back into view (2026-10-01)
`make bench-scroll` builds a signed Release copy and records two histories one after the other: `mixed` (1,200 clips: text,
links, code, colors and 100 screenshot-sized pictures) and `large` (5,000 text clips).

| History | Build | Hitches | Hitch time | Frame lifetime p95 |
|---|---|---|---|---|
| mixed | thumbnail cache off | 32 | 267 ms | 34.8 ms |
| mixed | thumbnail cache on | 6 | 50 ms | 28.0 ms |
| large (text) | cache off | 319 | 2,662 ms | 35.4 ms |
| large (text) | cache on | 3 | 25 ms | 28.6 ms |

The cache stores the decoded picture for a card that scrolls out and back, so it no longer decrypts the whole blob, shrinks it
and decodes the result again. The text history does not touch the cache: the 319 hitches in its "off" run came from the
Mac being busy, not from the code, so single runs vary a lot and only a large gap means something. Run it twice before
believing a small difference.
