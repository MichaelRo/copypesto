# Features/Settings — notes

- **Settings follow `docs/design-language.md`** (ADR 0012, seven panes: General, Appearance, Privacy, Shortcuts, Collections, Snippets, Data), each opening with `SettingsPaneHeader` pinned above the form by `settingsPaneTop`; a setting lives in one place and a read-only row never repeats a toggle. Never put `.fixedSize(vertical:)` on text in a pane header: the window's minimum size is measured at zero width, so the text counts as hundreds of points tall and the whole Settings window draws shifted up under its title bar. A new theme must pass the contrast and distinctness tests in `AppThemeTests` (ADR 0013). A shortcut recorder must pause the global hotkeys while it listens (`HotkeyController.suspend`/`resume`).
- **The sidebar is a `List` of button rows with its own selection pill** (`listRowBackground`, ↑/↓ through `onKeyPress`) on an opaque ground. A `List(selection:)` paints its selection in the system accent and ignores `.tint` (the first version of A-10 did, and white text on that blue failed the audit), and a translucent sidebar failed the contrast audit on the rows over a busy wallpaper. Type-to-select is not offered. Rows keep the `settingsSidebar(<pane>)` identifier.
- **A shortcut row has two states: keycaps, or a dashed "Record Shortcut" slot.** The recorder announces when it starts listening, what it accepted and why it refused (`Announcer`, refusals with high priority); its accessibility value stays the glyph string because the UI tests read it. Change, Reset to Default and Turn Off live in one trailing menu (`shortcutMenu(id)`); a UI test opens it and picks the item by title.
## Lessons

- **Opening a pane must not read the Keychain.** A pane that read the backup key to decide whether to show Show Recovery Key prompted for Touch ID or the password. Panes decide from a preference ("a backup was ever written"); `AutoBackupService` reads the key once per launch.
- **A grouped `Form` paints a card behind any `Section`**, so a pane header cannot be a section with a clear row background. One extra row in Appearance's first section pushed the card-size slider below the fold; a new control there goes in its own section. The two 92 pt picture pickers (Shelf position, Light and dark) do the same: Cards stays above them, because the card-size UI tests drive the slider and the preview at the top follows it.
- **A registered Carbon hotkey is consumed before any window sees the key**, which is why recording the combination already in use opened the shelf; the recorder pauses the hotkeys while it listens.
- **A menu item whose target does not respond to its action is disabled by AppKit.** Quit Pesto was grayed out for months because its target was the app delegate, which has no `terminate:`; aim it at `NSApp`.
- **`SMAppService.Status.notFound` means "not registered yet"**, not "cannot be registered"; show a reason only after `register()` throws.
- **Status text uses `Color.statusGood` and `Color.statusBad`**; the system `.green` and `.red` fail contrast on light rows. Captions use `View.pestoCaption()` (70% of the primary color), because `.secondary` on a grouped row is only 3 to 4:1.
- **`XCUITest` exposes a child `Text` inside an `.accessibilityElement(children: .combine)` row as `value`**, and nesting a labeled child inside a combined element makes the audit report "Parent/Child mismatch"; one `HStack` with `.ignore` and one label is clean.
- **A `.task` or `.onAppear` on a `Group` whose content is empty never runs**, so a section that loads what decides whether it shows (Found on this Mac) can never appear. Load it where it is always on screen (`DataPane.onAppear`, `AppState.refreshInstalledImportSources`). A hosted test cannot see it; `ImportOfferUITests` did.
- **A SwiftUI `Menu` in a settings row exposes no press action on macOS 27**: VoiceOver's Space did nothing on a shortcut's options menu and the audit said "Action is missing" (2026-10-23; a label, `.borderedButton` and `.borderlessButton` did not change it). Use `PopUpMenuButton`, a `Button` that pops a native menu. A pop-up `Picker` is fine: it works with VoiceOver even though the audit reports the same finding on it (`AccessibilityAuditTests.popUpButtons`).
- **A tile in a set of choices (theme, icon, swatch, symbol) uses `.selectableTile`** (name, button role, selected trait, press action in one place; `SelectableTileScanTests`). A `Button` whose content is ignored loses its press action. Unselected tile text uses `AdaptiveContrast.quiet`, never `Color.secondary` (`QuietTextScanTests`).
