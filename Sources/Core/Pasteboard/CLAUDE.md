# Core/Pasteboard — notes

Clipboard watcher, type detection, classification, and exclusion rules. Sendable, no SwiftUI (see `AGENTS.md` for module boundaries and security invariants).

## High-Risk Zones

| Path | Blast radius |
|---|---|
| `PasteboardWatcher.swift` | Polls `NSPasteboard`; a stall or wrong cadence drops or duplicates every captured item. |
| `SourceAppResolver.swift` | Resolves the originating app at ingest; wrong timing misattributes every item's source. |
| `ExclusionRules.swift` | `excludedBundleIDs` is **append-only** — removing an entry requires an ADR + reviewer approval. |

## Key Invariants

- **`Timer` vs `DispatchSourceTimer` in the watcher.** Runloop `Timer`s stop firing under modal sheets. We use `DispatchSourceTimer` on a serial queue. Don't switch back.
- **Capture frontmost app BEFORE showing the overlay.** Once `OverlayPanel` is shown, *we* are frontmost. `SourceAppResolver.resolve(bundleID:)` is called at ingest, not at render, and draws the icon on the main actor (`NSBitmapImageRep` is not thread-safe), once per app per process: the drawing lives in `SourceIconCache`, which ingest and the cards share (`SourceIconSharingTests`).
- **`PasteboardWatcher.resume()` must sync `lastChangeCount = pasteboard.changeCount` before clearing `isPaused`.** Syncing at `pause()` time is wrong — the board can change during the pause window. Syncing at `resume()` prevents the first tick after resume from replaying events that occurred while paused.
- **Picture screening is best-effort and says so (ADR 0005).** `OnDeviceImageScreener` shows the picture to Apple's on-device model with a trivial prompt and treats a guardrail stop or refusal as "sensitive"; no Apple Intelligence means nothing is flagged. The old Sensitive Content Analysis path was deleted (it needs an entitlement Pesto lacks). Links are checked by `NSFWURLDetector` (blocklist, host stems, keywords, page metadata, then the linked picture); any card can be marked by hand. Tests inject `ImageSensitivityScreening`.
- **`tick()` reads the pasteboard before its first `await` and re-checks `changeCount` after the last one.** A write that lands during the frontmost-app hop must not be judged by the previous copy's types (a concealed password would be ingested). Rich text (`.rtf`/`.rtfd`) is flattened to its plain string at capture; storing raw RTF skips classification, masking and previews, and pastes back as markup.
- **`StorageService.appendToLatest` must apply the same sensitivity policy as `ingest`.** A combined text that trips `SensitiveContentDetector` gets a masked plain preview, and an item that was already sensitive stays so.
- **The 8×8 pHash only nominates duplicate images.** A candidate is a duplicate only if `PerceptualHasher.pixelDigest` matches; the hash alone drops distinct screenshots.
- **A remote copy (Universal Clipboard, `com.apple.is-remote-clipboard`) has no source app.** `PasteboardCapture.sourceBundleID` is nil when `isRemote`, because the frontmost Mac app is not where the text came from; the card shows a phone glyph and "Another device". It is kept only when `Setting.keepsRemoteCopies` is on (off by default, ADR 0004): `ExclusionRules.blockReason(isRemote:)` returns `.remoteCopy` first, then judges a remote copy by its markers alone and never by the frontmost or recent Mac apps (an excluded password manager in front did not copy it). A re-copy of the same content updates `isRemote` and the source in `popExistingDuplicate`; backups carry `isRemote`.
- **Image sensitivity cannot use `SCSensitivityAnalyzer`.** It reports nothing without the `com.apple.developer.sensitivecontentanalysis.client` entitlement, which Pesto does not have; `OnDeviceImageScreener` (guardrails, ADR 0005) is the only image path. `PasteboardTypeDetector.priorityOrder` ends with PDF and SVG on purpose: apps that copy text often add a PDF of it, and ranking it higher would turn ordinary text copies into PDF clips.
- **Never decode a clipped picture at full size: go through `ImageDownsampler.boundedImage` (ADR 0006).** Decode cost follows pixels, not bytes (a 7 MB flat PNG at 400 MP took text recognition to 3.9 GB), so a new reader of picture pixels (OCR, the pixel digest, a classifier) uses the 24 MP limit or `ImageDownsampler.thumbnailPNG`. The byte limit of ADR 0006 does not protect it.
- **The watcher's period follows input (`PollPolicy`, ADR 0006)**: 60 ms for three seconds after the last key or click, 200 ms, then 500 ms after half a minute. It is adaptive only in the app (`start(adaptive: true)`); the idle CPU test uses the fixed 200 ms. `NSPasteboard.setData` does not bump the change count, so a writer that calls `clearContents()` and then spends time before `setData` can hide its clip from a poll that lands between: build the data first.
- **A mask is dots and a count, never the badge's label** (`SensitiveContentDetector.hiddenCountMask`, `dotsOnlyMask`): the card wears the category as a badge, so "API key ••••" said it twice. What the badge cannot say stays in the mask (a vendor and prefix, the last four digits, the app that hid a credential). A mask is stored, so changing its wording needs `modernisedMask` and a launch migration for rows already stored (`Secret masks`); search finds a hidden clip by `SensitivityCategory.searchName`.
- **`NSPasteboard` is not `Sendable` and Pesto does not say it is.** Code that reads from any thread (the watcher's actor, a notification handler, `TemplateExpander`) uses `AppPasteboard.reader`, a `SystemPasteboard` that only reads; code that writes uses `AppPasteboard.general` on the main actor (`AppState.writeToPasteboard`, the intents). `OwnWriteGate.write` takes anything with a `changeCount` (`ChangeCounting`). `RetroactiveConformanceTests` fails on a new `@retroactive @unchecked Sendable`.
- **The watcher reads a flavour once and judges its size before it reads anything else** (S-25): macOS gives no length before `data(forType:)`, so the text is read as bytes, decoded from those bytes, and a copy over `ClipSizePolicy` skips its rich flavours and goes on to ingest, which refuses it with a message. A new read of a board goes through `FakePasteboard.contentReads` in `PasteboardBoundedReadTests`.
- **Markdown text is `.text` with `detectedLanguage == "markdown"`** (`MarkdownDetector`, two kinds of markup needed), so `@markdown` finds it without a new type. Every place that rewrites a clip's language after a re-read keeps it for `.text` as well as `.code` (`StorageService+SemanticIndex`, `+Repairs`, `+Snippets`), and `PredicateRuleSet.contentShape` does not call it code. The classifier migration is version 4 (3 for Markdown, 4 for `json`, a parsed object or array; `JSONText`).
## Lessons

- **Rank GIF above PNG and TIFF.** A browser copy of a GIF carries a still beside the GIF; ranking the still first stored a still. LinkPresentation returns GIPHY pictures as animated WebP, which `NSImageView` cannot play, so `ImageDownsampler.animatedGIF` re-encodes any multi-frame source (WebP, APNG) as a GIF. A stored still is a capture bug, not a drawing bug.
- **A card number inside longer text is masked only with 13 to 19 digits, a Luhn pass and a real issuer prefix**, because epoch timestamps and order numbers pass Luhn one time in ten (`SensitiveContentDetector`).
- **An app that just lost focus is still a possible source.** `FrontmostHistory.bundleIDs(within:)` counts an entry until the next activation plus the window; filtering by activation time hid a password manager that was left 100 ms ago. The frontmost app is still read through a main-actor hop, so a busy main thread widens the race.
- **Bound every classifier quantifier.** `ContentClassifier`'s SQL anchor and structural brace pattern are quadratic on text that only looks like the start of SQL or code (360 KB of `SELECT a ` ran past 60 s); heuristics run over `maxAnalysedCharacters`, and `ContentClassifierTests` has an adversarial case with a time limit.
- **A claim that something is not read needs a fake that counts reads** (`FakePasteboard.contentReads`); a remote copy was read before it was dropped and nothing failed.
- **Check detector fixtures against the real world, not the code under test.** The screen-share detector listed three bundle IDs that matched no real app (`osascript -e 'id of app "FaceTime"'` gives the real one) and its tests used the same wrong strings. The no-permission signal for a Chromium share is an onscreen window at layer 25, about 439 by 60 (`BrowserShareSignature`).
